# Global Property Valuation AI

A reproducible, multi-specialist property valuation training system for residential, commercial and land assets.

## Important status

This package is a **training pipeline and model architecture**, not a pre-trained global AVM. No transaction dataset was supplied, and global transaction microdata is not uniformly open or licensed. The `models/` directory is intentionally empty. A model must not be represented as trained until `train.py` has been run on real, licensed, quality-checked transaction data and the evaluation gates pass.

## Architecture

Specialist model families:
1. Transaction/comparable-sales model
2. Government/cadastral and planning model
3. Satellite/built-environment model
4. Geospatial accessibility model
5. Traffic/mobility model
6. Population/demographic model
7. Market-cycle model
8. Physical-property model
9. Development/infrastructure model
10. Rental/investment model

The current runnable tabular pipeline trains one CatBoost model per specialist feature group when that group has sufficient labelled records, plus a generalist model using all available features. It does not yet claim a calibrated stacked ensemble; that should be added only after out-of-fold and geographic validation are implemented. The current implementation uses CatBoost if installed and falls back to HistGradientBoostingRegressor. Imagery embeddings should be generated by a separate computer-vision feature extraction service and joined by `property_id`.

## Quick start

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Prepare `data/processed/property_training.csv` using `configs/schema.yaml`.
Required target columns:
- `sale_price` (numeric, local currency)
- `currency` (ISO 4217)
- `country_code` (ISO 3166-1 alpha-2)
- `asset_type` (`residential`, `commercial`, `land`)
- `transaction_date`
- `land_area_sqm` or `built_area_sqm` (at least one)
- `latitude`, `longitude` recommended

Then run:
```bash
python src/train.py --data data/processed/property_training.csv
python src/evaluate.py --data data/processed/property_training.csv
```

Artifacts are written to `models/` and metrics to `reports/`. Do not pool raw nominal prices across currencies. The pipeline derives a local-currency price-per-sqm target and trains by country/asset-type cohorts. Cross-country global output should be normalized using FX/PPP and country/local market calibration, not a single unqualified currency target.

## Data policy / no leakage

- Keep a source, licence, observation date and geographic coverage for every input.
- Do not use post-transaction features to predict historical transaction prices.
- Use time-based holdout and geographic holdout; random row split alone is insufficient.
- Exclude personal identifiers and sensitive owner/occupant data.
- Respect each source's terms, attribution and redistribution rules.
- Never infer legal title, structural condition or exact floor area from satellite imagery alone.
- Treat asking prices as a separate weak-label dataset, not equivalent to closed transactions.

## Data acquisition starter sources

See `DATA_SOURCES.md`. Start with country-specific transaction microdata (UK, France, selected US counties, etc.) and add global covariates. Global satellite/building/population/road data do not replace transaction labels.

## Feature clusters

The full list is in `configs/schema.yaml`. Missing features are allowed; each specialist only trains if it has enough usable rows and non-constant features. Model outputs include which specialists contributed.

## Evaluation gates

The evaluation script reports MAE, RMSE, median absolute percentage error, R², and error by country/asset type. Deployment should require:
- no train/test temporal leakage;
- holdout geography not seen in training;
- adequate sample size per market cohort;
- calibration/coverage checks for valuation intervals;
- documented source provenance and permitted use.

This is decision support, not a certified appraisal. A licensed valuer and local legal/tax checks remain necessary for high-stakes use.
